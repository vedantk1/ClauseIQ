# Product images

These three reviewed Black-theme captures show the actual application. They are
not generated mockups or retouched representations of application behavior.

| File | Viewport | Demonstrated state |
| --- | --- | --- |
| `review-workspace.png` | 1440×1000 | Authored service-credit finding, verbatim evidence and physical-page links |
| `library-answer.png` | 1440×1120 | Authored partial answer beside Keyword results, with its own source excerpt expanded |
| `my-review.png` | 1280×800 | Two authored saved questions, a revisit marker, a marker-only finding and export controls |

The captures use the isolated Playwright journeys in
`frontend/e2e/workspace.spec.mjs`, with test-owned API responses derived from
`tests/fixtures/pdfs/managed-services-25p.pdf` and the authored review fixture under
`backend/fixtures/reviews`. The Findings view selects **Clarify how service credits
are earned**. Synthetic/example labels remain visible. Test source spans are
derived from the exact PDF through PDF.js; these captures do not run the backend
extractor.

The Library response is authored in `frontend/e2e/fixtures.mjs`, not generated by
a provider. Its extension period and request window are checked against a complete,
contiguous sentence from clause 73 on physical page 25 of the PDF extraction.
The quote is sliced from that extraction without joining missing text. Remaining
conditions are explicitly outside the excerpt; the response stays partial and
the continuation flag is retained. A distinct page-24 hit is deliberately present
to exercise answer-owned attribution rather than silently selecting the first hit.
This fixture is a UI demonstration, not retrieval-quality or answer-quality evidence.

The My review questions and markers are seeded, test-owned personal state. Export
checks confirm that saved wording is included and unsaved edits/Ask answers are
excluded. Real database persistence is tested separately, not established by an image.

No real installation, account, credential, private agreement or saved personal
work is used. Browser chrome is excluded. The mocked API state demonstrates the
frontend's presentation; the images do not demonstrate database persistence,
live AI generation, citation support for every claim or legal accuracy.

## Regeneration

With the dependencies and Playwright Chromium installed, run from the repository
root:

~~~bash
npm --prefix frontend run test:e2e -- --grep 'Black and Graphite|workspace drafts|Library answer journey'
~~~

The selected outputs under ignored `output/playwright/showcase/` are:

- `review-workspace-black.png` → `docs/images/review-workspace.png`
- `library-answer-source-black.png` → `docs/images/library-answer.png`
- `saved-review-black-1280.png` → `docs/images/my-review.png`

Visually review each regenerated image before copying those exact files. Keep
Graphite, narrower layouts and other diagnostic captures local; do not copy the
whole generated output directory. No real keys or backend are used. The Library
journey's confirmed-send route is explicitly intercepted by its provider stub,
and unexpected/external requests still fail the check.

[repository policy](../REPOSITORY_POLICY.md) for the publishing boundary.
